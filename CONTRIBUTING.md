# Contributing

Short version: find a task → fork → open a PR → wait for review.

## 1. Find something to work on

Check the repo's open issues. No suitable issue? Open one first describing
the problem — drive-by PRs without context are likely to be closed.

## 2. Fork and branch

Fork the repo, create a branch named after what it does
(e.g. `fix-login-timeout`, `docs-zh-readme`).

## 3. Open a pull request

Fill in the PR template:

- **What changed** — one paragraph, plain language
- **How you verified it** — commands run, tests, screenshots
- **Linked issue** — `Closes #123`

Keep PRs small and focused: one change per PR.

## 4. Wait for review

Every PR gets a human review. Expect questions, not just approvals —
that's how the bar stays high.

## Ground rules

- **No secrets in PRs.** No tokens, keys, or credentials — not even "test" ones.
- Docs fixes are first-class contributions.
- Be kind. See [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).
